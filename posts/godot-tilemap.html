TileMap 换成 TileMapLayer 之后，我踩的五个坑

2026.09.15 / 10 分钟 · 约 2,200 字 / Godot 4.6 · 2D 俯视

项目从 Godot 4.3 升级到 4.6。升级提示里最刺眼的一条是旧的 TileMap 节点已经弃用，4.6 之后建议全部换成 TileMapLayer。我原以为是把节点换个类型，实际上是把「一张地图五层」拆成「五个节点各自一层」，很多默认行为跟着变了。

迁移本身花了半天，改完之后修接缝和排序又花了三天。这篇按踩坑的顺序写。

为什么必须换

4.6 里旧节点还能跑，但编辑器会一直给黄标，导出模板也开始提示。项目还在早期，早换比晚换便宜。我的地图是五层：地面、地毯与地砖、家具、人物与灯具、遮挡物（比如头顶的吊灯和门框）。

换成 TileMapLayer 之后，结构变成五个同级节点，每层单独设置纹理、碰撞、排序和导航。好处是清楚，坏处是以前那些「自动继承」的东西全要自己接一遍。

坑一：y-sort 不再是地图级别的开关

旧 TileMap 有一个全局的 y_sort_enabled，打开之后同层的图块会按 y 排序。新节点是每层一个开关，而且它只管「这一层内部的图块之间怎么排」，跨层要靠 z_index。

我一开始只给家具层开了 y-sort，结果角色永远站在家具后面——因为角色和家具不在同一个排序组里。正确的做法是把地图拆成三段：

  • 地面与地毯：z_index = -1，不需要 y-sort；
  • 家具、角色、灯具：z_index = 0，全部开 y-sort，它们才会互相遮挡；
  • 遮挡物：z_index = 1，永远在人前面。

关键点是角色也得参与同一套 y-sort。角色是 CharacterBody2D，它的 y_sort_enabled 要打开，同时它的 position.y 要代表「脚底」，不是中心点，否则站在桌子旁边会被桌子拦住半个身子。我最后给每个角色场景加了一个 Marker2D 当脚底锚点，用它的全局 y 去比较。

# 角色根节点的 y 用脚底，而不是贴图中心
func _process(_delta: float) -> void:
    var feet := $FootMarker.global_position.y
    global_position.y = feet

坑二：每层都会生成自己的碰撞体

旧 TileMap 的所有层共用一个物理体。拆成五个节点之后，每层都会生成自己的 StaticBody2D。我给「地毯」层误开了一个碰撞多边形，结果角色在地毯上走两步就被弹开，找了半小时才想到去看碰撞层。

现在的做法是：只有一层负责碰撞（地面与墙），并且把它设成不可见、放在最后绘制；其他层全部清空物理层。这样也顺手解决了另一个问题——家具层的桌腿不应该挡住玩家，真正该挡的是桌子中心那一格。

改完记得在调试里打开「可见碰撞形状」，一次性看全，比在场景里逐个点快得多。

坑三：无缝地图的接缝又回来了

这是最费时间的一个。旧版本里我用了 texture_filter = nearest 和图集边缘留白，地图拼起来看不出缝。换节点之后，接缝又出现了，一条一像素的亮线，斜着看更明显。

原因是新节点的纹理设置不再从 TileSet 继承，每层要单独设。还有一个更隐蔽的点：图集里每个图块的四周要留 1px 的 extrusion，不然采样到边缘时会把隔壁图块的像素吸进来，尤其是开了 mipmap 的时候。

我的处理顺序：

  1. 导入图集时关闭 Filter 和 Mipmaps；
  2. 每层 texture_filter 设成 Nearest；
  3. 图集每格四周加 1px 的边缘复制；
  4. 相机位置取整，避免半像素采样。
# 相机跟随也取整，否则滚动时整张地图都在抖
func _process(delta: float) -> void:
    var target := player.global_position
    camera.global_position = target.round()

坑四：图层顺序不等于节点顺序

TileMapLayer 的绘制顺序由节点在场景树里的顺序决定，z_index 会插在这个顺序中间。我调整过一次场景结构，把遮挡层挪到了角色前面，结果所有门框都盖住了 UI——因为 UI 在同一棵 CanvasLayer 里，z_index 比遮挡层低。

最后的规矩很简单：地图五层固定放在一个 Node2D 里，只在这个容器内部用 z_index 排；角色放在同一个父节点下；UI 一律走独立的 CanvasLayer。三块互不干扰，谁也别想盖住谁。

坑五：寻路网格要单独合

原来一个 NavigationRegion2D 直接烘整张地图，五个层的信息一起算。现在是五个节点，如果每层都烘一次，角色会在「地毯可走」和「地面可走」两张网格之间来回跳。

解决办法是只让碰撞层参与导航：在 TileSet 里给可行走的图块设 navigation polygon，其他层关闭 navigation layer，然后只对碰撞层烘一次。烘焙完成后用 NavigationAgent2D 调试，看路径是否贴边——如果总是绕着家具走一格，说明家具层的导航没关干净。

换完之后

  • 接缝消失，1080p 下放大到 3 倍也看不到亮线；
  • 同屏 42 个可交互图块加 8 个角色，帧时间从 6.8ms 降到 4.1ms；
  • 场景文件更好读：五层各一个节点，改哪层一目了然；
  • 新加一层（比如「积水」）只需要复制一个节点，不用再拆图。

如果你也在迁移，建议按这个顺序做：先拆层、跑通绘制，再处理碰撞，最后才是排序和导航。反过来做会同时面对三个变量，很难判断是哪个出的问题。
